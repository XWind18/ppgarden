## 安装与更新

按上表选择需要的脚本，打开对应的「安装／更新」链接。

- 桌面：安装 Tampermonkey 等脚本管理器，再打开上面的链接安装，访问 <https://ppgarden.top/> 使用。
- iPhone／iPad：在 Safari 打开安装链接，再打开 Userscripts 扩展，按安装提示安装或更新。也可将 `.user.js` 文件保存到 Userscripts 的脚本目录。
- 已从本地文件安装的版本，先通过此链接覆盖更新一次，让脚本携带 GitHub 更新地址；避免同时启用两份同名脚本。
- Tampermonkey 按管理器的更新设置检查新版本，也可在管理器中手动检查更新。
- Userscripts 在扩展的「可用更新」中查看并应用新版本；未检测到时，可重新打开安装链接覆盖更新。安装及更新方式见 [Userscripts 官方说明](https://github.com/quoid/userscripts#usage)。

脚本使用 `@version` 检测版本，`@updateURL` 指向对应的 `.meta.js`，`@downloadURL` 指向完整的 `.user.js`。安装时只需 `.user.js`；任务脚本的截图组件由脚本管理器按脚本声明加载。后续安装链接保持固定，无需部署服务器。

## 花朵交易助手

- 在花朵交易页（`#trade`）右下角点击「可交易花朵」，打开独立的 div 悬浮窗。
- 按网站账号顺序分组，每个账号内按 **每组出价数值从高到低** 排列；显示花名、品质、每组出价、每组实得时长、库存朵数和本次可卖组数。
- 同花同品质在每个账号下只显示一条，选择该账号能成交的最高报价；最高价不能成交时继续检查较低报价。相同价格优先保留可卖组数更多的求购。
- 点击花名定位并高亮原页面求购；点击「卖给他／接单」打开网站原有的求购详情，并预选这一行所属账号。定位会切换对应账号、进入求购大厅并清除品质、价格及「只看我能卖的」筛选。遇到同花同价的多张求购，会核对详情中的求购编号，编号失效时提示刷新。
- 快捷入口只打开原站确认，不提交成交请求；最终数量、价格和账号由网站重新读取，你核对后再确认。
- 读取网站的交易规则、各渠道求购、每个账号的原始仓库库存与逐单 `sell-quote` 核验；可卖组数以手动接单的服务器核验为准，受库存、额度、占用和买家剩余需求限制。不会仅凭页面存在「接单」按钮就判定能卖。
- 自动出售关闭、单花未启用出售时，仍核验手动「卖给他／接单」的机会；不使用受自动出售开关影响的 `sellable-stock` 接口，修复有库存却显示「出售已暂停／0 项可交易」的问题。
- 排除自己的求购、过期或暂停的求购、正在游戏或队列已满的买家、已满足的需求、缺失库存快照及服务器阻止的账号。全部账号交易暂停、本号交易暂停、团单暂停等状态会单独显示。
- 实得时长作为主要金额大字显示，原始出价放在下方，金额均读取网站核验结果。
- **求购出价范围**：默认 **20～144分钟/组**，包含上下边界；在悬浮窗中设置最低、最高出价，任意一项留空表示不限。范围在逐单 `sell-quote` 请求前生效，范围外不查询报价；账号、求购大厅仍需读取，库存按缓存规则复用。筛选按求购出价，不是扣除后的实得；设置自动保存在当前浏览器。
- **长期仓库缓存**：按账号及渠道在当前浏览器本地保存仓库接口返回的完整花朵库存和原始时间，跨完整查询及网页重载保留。读取后 **30分钟内**、且仍在同一北京时间日期时复用，缓存命中不重复读取该账号仓库，也不延长缓存有效期；续拉时若内部仓库缓存已过期，同样重新读取；到期、时钟回退或渠道变化时重新读取，解绑账号会移除缓存。求购大厅、账号权限、逐单报价每个新查询轮次仍重新核验，实得、展示库存和可卖组数以本轮报价为准。
- 每个账号下分别显示「仓库读取／仓库缓存／仓库断点」、读取时间和原站同步时间。**30分钟按接口读取时间计算，不代表游戏数据刚同步**：原站即使两天前同步，也原样显示旧时间并提示数据较早；未提供同步时间时明确显示未知。
- 「更新仓库」放弃当前断点，重新读取仓库和交易机会，继续遵守2～3秒间隔及429冷却，不改变自动刷新开关；它只读取原站已有快照，不触发游戏同步。买入、采收等造成库存变化后可主动更新；打开原站卖出确认时会失效该账号缓存，下次查询重新读取。手动刷新当天已停刷的账号时会单独重读其仓库，核对额度是否恢复。
- **断点续拉**：关闭窗口、切页、进入后台、网络错误或429中断后，将本轮已完成的求购、各账号库存和核验结果保存在本地。重新打开、回到前台或点击「继续读取」时，先重新检查账号和交易权限，再继续未完成部分。429冷却与请求间隔也保存，刷新网页后仍可继续；「重新查询」会放弃断点，重新核验全部数据。
- 断点自本轮开始起 **30分钟内**有效，跨北京时间零点、修改价格范围、账号或交易规则变化时重新读取；完整完成后清除断点。续拉结果保留本轮最初开始时间，不会将其当作刚同步的库存；成交前仍由原站核验。存储失败时提示，当前页面内仍可继续，重载后需重读。每个浏览器只保存最近一轮未完成读取。
- 首次打开读取列表；切换页面或重新打开悬浮窗时保留当前列表，刷新间隔内不重复加载。窗口中的「自动刷新」开关**默认关闭**，间隔默认 **10分钟**，可设为 **3分钟及以上的整数分钟**；开关和间隔均保存在当前浏览器，更新脚本保留已有选择。修改间隔从当前时刻重新计时，不会打开自动刷新；关闭后仍可手动刷新。
- **各账号独立停刷**：网站返回的今日卖出交易笔数达到20次（网站限制更低时按更低值），或今日剩余上架次数为0、报价明确提示「无上架次数」，只停止该账号当天的自动查询；其他账号继续刷新。各账号的停刷原因保存在当前浏览器，重新加载时先核对绑定账号，跳过已耗尽账号的库存和报价。所有账号都耗尽后，当天不再自动请求，按北京时间次日零点解除；保持窗口打开且自动刷新已开启时恢复一次核验，否则下次回到前台或打开窗口时处理。
- 手动「刷新列表」仍可重新核验停刷账号，明确读到额度恢复后解除该账号的当天暂停。未知次数、过期的游戏快照、在途订单占用、暂时没有空货架、无库存及接口失败都不当作当天耗尽。次日恢复不会开启用户手动关闭的自动刷新。
- 关闭窗口、离开交易页或页面进入后台时暂停并取消未完成读取；回到前台且窗口打开时继续本轮断点，完整轮次则仅在自动刷新开启且到期时重新查询。不会在后台累积请求；自动刷新关闭仍可继续用户已开始的本轮查询。
- 没有断点时，「刷新列表」重新读取账号、交易权限、求购和报价，仓库优先复用有效缓存；有断点时按钮显示「继续读取」，另有「重新查询」用于从头刷新。修改价格范围会取消正在读取的旧轮次、清除旧结果，点击刷新即可按新范围查询，不会自动开启自动刷新。
- **统一请求间隔**：账号、求购大厅、各账号库存和逐单报价全部依次读取；上一次请求结束后等待 **2秒＋随机0～1秒** 再发下一次，首次打开可立即读取。手动刷新、跨轮刷新也遵守同一间隔；等待中关闭窗口、切页或进入后台会取消后续请求。各有货账号都已找到更高价后跳过同花较低报价；查询过程中逐步显示已核验结果。账号或求购较多时，整轮完成时间会相应增加。
- 遇到429停止请求并保留部分结果，按服务器 `Retry-After` 冷却（未提供时60秒）；冷却期间重复刷新不会发起请求。间隔和随机延迟用于减少集中读取，网站限流阈值未知，不能保证不会触发风控；仅约束此页面中交易助手发起的请求，不包括原网站或其他标签页。
- 脚本的数据调用均为同站 GET，不保存凭据、不发送到其他网站、不自动下单或更改出售设置。断点包含本轮的账号、库存和报价快照，仓库缓存保存各绑定账号最近一次读取的库存；均仅保存在当前浏览器的网站存储中。断点完成或失效时清除，仓库缓存保留到下次更新、解绑或权限失效；清除网站数据也会删除缓存、断点及设置。缓存保存失败时用div提示，当前页面仍可复用，重新加载后需重读。
- 悬浮窗跟随页面深浅色；手机按钮至少44px，并自动避开底部导航；原站账号菜单、功能菜单或求购详情打开时收起悬浮窗，避免遮挡菜单。
- 无库存时显示空状态；登录失效、网络错误、请求频繁或接口格式变化时显示具体提示。接口只返回部分求购、求购在核验中发生变化时会提示覆盖范围；读取中断时把已核验结果标为部分结果。
- 列表使用本轮返回的求购及报价，仓库候选筛选可使用带时间标记的缓存。每种花的可卖组数单独核算，共享库存及账号额度，不能把各行组数直接相加当成同时可成交总量。成交前应回到网站进行确认。

## 发布新版本

1. 修改正式脚本，将 `@version` 改为更高的版本，并更新本说明中的版本号。
2. 同步检测文件并检查语法：

   ```sh
   node scripts/sync-metadata.mjs
   node --check ppgarden-task-layout.user.js
   node --check ppgarden-task-layout.meta.js
   node --check ppgarden-flower-trade.user.js
   node --check ppgarden-flower-trade.meta.js
   git diff --check
   ```

3. 查看并提交改动，推送到 `main`；发布脚本和 `.meta.js` 时使用同一次提交，保证版本一致：

   ```sh
   git add ppgarden-task-layout.user.js ppgarden-task-layout.meta.js ppgarden-flower-trade.user.js ppgarden-flower-trade.meta.js README.md scripts tests
   git diff --cached
   git commit -m "Release v1.8.10"
   git push origin main
   ```

提交信息中的版本号按实际版本调整。首次从终端推送需要配置该 GitHub 账号的 Git 身份验证。

## 文件存放

```text
ppgarden/
├── README.md                         # 使用说明和文件入口
├── .gitignore                        # 本地预览及导出文件不纳入版本控制
├── ppgarden-task-layout.user.js       # 任务／花圃设置安装脚本
├── ppgarden-task-layout.meta.js       # 任务脚本版本检测
├── ppgarden-flower-trade.user.js      # 花朵交易助手安装脚本
├── ppgarden-flower-trade.meta.js      # 交易助手版本检测
├── scripts/                          # 元数据同步工具
├── tests/                            # 浏览器自检脚本
├── previews/                         # 本地界面与功能预览
└── exports/                          # 本地已生成的完整 PNG 长图
```

- 正式脚本始终保留在根目录，更新时直接修改同一个文件。
- 自检脚本放在 `tests/`，使用 `ppgarden-功能名.self-check.js` 命名。
- 界面截图、对比图、移动端预览放在 `previews/`。
- 导出或复制生成的完整长图放在 `exports/`。
- 历史预览和长图仅供参考，可能与当前版本的设置不同。
- 公共仓库包含正式脚本、版本检测文件、说明、同步工具和自检代码；`previews/` 与 `exports/` 是本地调试产物，不纳入版本控制。

## 使用要点

- 任务中心右下角提供「任务设置」和「复制长图」。
- 手机悬浮按钮自动避开网站底部菜单，菜单上方保留至少12px间距；状态提示、设置窗与页面底部留白同步调整。菜单隐藏后恢复原间距，窗口尺寸、滚动和可视视口变化时重新定位。
- 设置窗支持每行数量、卡片最大宽度、最小高度、信息显示和筛选；任务中心另有背景色开关。
- 原页面「只看可接取」右侧增加「只看待刷新」按钮，与设置窗内的同名选项双向同步、自动保存。选中时显示蓝色底色、亮色边框和「✓」，适配深浅色主题；取消选中后恢复普通样式，按钮宽度不跳动。两项筛选互斥，开启其中一个会关闭另一个；工具栏动态替换后仍会恢复按钮和选中状态。
- 任务中心的「任务样式」标题与「新版／经典版」切换按钮放在同一行，按钮高度44px，选中项显示边框与勾选标记；支持手机触控、键盘和深浅色主题，点选即生效。新版为原有图文布局，经典版为2px密排小卡片、内容居中、积分在下方、倒计时／进度放在底部。升级脚本后保留已有设置，首次使用继续默认新版。
- 在「任务设置」点击「经典方案」，一键使用经典版、浅色截图、默认排序、3列、最大190px和最小60px，显示任务图片、编号、任务内容、积分、类型、接取／升级人、进度和倒计时。任务图片以24px小图居中显示在内容上方，默认隐藏培育状态、任务状态和预约提示，仍可逐项勾选；「截图方案」可恢复新版图文方案。
- 更新后继续沿用已保存的字段设置；旧经典方案未显示图片时，可重新点击「经典方案」，或直接勾选「任务图片」。图片可随时取消勾选，页面、导出和复制同步生效。
- 「他人升级」读取原页面的升级人姓名，直接显示为「昵称 升级」，合并重复的升级人提示，新版、经典版及长图同步生效。取消「接取／升级人」勾选或原页面未提供姓名时，保留「他人升级」；隐藏「任务类型」后仍可单独显示升级人，不会将接取人当成升级人。
- 经典版按任务状态配色：可接取浅绿、待刷新米黄、已接取浅粉，深色主题使用对应暗色；「显示背景色」开关控制配色。新版继续按升级前的原始分配色。页面、导出和复制使用同一份任务样式设置。
- 经典版仅保留经典布局、间距、图片尺寸和状态配色，字体、字号、字重、行距与窄卡片自适应规则共用新版方案：正文13px（窄卡片12px）、积分与编号12px、接取／升级人10px、任务类型11px、倒计时13px（窄卡片12px）。正文占满可用宽度，底部按倒计时或进度的实际宽度分配空间，尽量单行显示类型与升级人；超长文字仍完整换行，每行按最高卡片自动撑高。页面和长图同步生效。
- 任务卡片默认每行 **3** 个、最大宽度 **190px**、最小高度 **60px**，默认勾选任务图片；「截图方案」也使用这组参数并显示图片。已保存的设置会继续沿用，点击「恢复默认」可应用新的默认值。
- 窄卡片缩小图片与间距，任务内容和接取人完整换行；每行按最高卡片自动撑高。手机设置窗提供至少44px触控区域和16px输入字号，打开时不会自动聚焦数字输入框。
- 任务中心支持导出 PNG 和复制长图，清晰度范围 **1–3 倍**，默认 **2 倍**，可输入小数。
- 截图主题独立于页面主题，默认浅色，可切换深色。
- 手机和 PC 的长图统一使用桌面布局，读取设置中的当前列数、最大宽度和最小高度。短任务文本单行显示，过长时自动换行并完整展示；最小高度是下限，内容较多时每行仍会自动撑高。
- 任务中心顶部提供三张独立时间卡片，依次显示「同步时间／下次任务刷新／当前时间」，长图第三张改为「截图时间」。标签与数值分行，数字使用等宽字体；截图中的三张时间卡片与任务卡片等宽，跟随当前列数排布。花圃保留原有时间行。
- 导出长图、设置窗复制和右下角复制前检查同步时间：与当前时间相差超过5分钟时，先显示 div 自定义圆角提醒弹窗，两张小卡片对比同步时间和当前时间，确认后继续，取消则返回页面同步；恰好5分钟不提示。弹窗适配深浅色与手机，默认聚焦取消，支持关闭按钮和 Esc，键盘焦点保留在弹窗内。无法识别同步时间时也先提示确认。支持跨天、跨年；图片中的截图时间以确认后的实际生成时刻为准。
- 同步时间读取原页面已有字段；下次刷新时间取页面已加载的待刷新任务中最短的有效倒计时，换算为具体日期时间，支持跨天。脚本内隐藏倒计时或筛选任务不会影响读取；页面没有待刷新任务时显示「暂无待刷新任务」，无法读取倒计时时显示「未获取」。
- 花圃支持独立显示设置与筛选，导出和复制长图仅用于任务中心。

## 设置历史与更新恢复

- 在设置窗底部展开「设置历史」，可点击「保存当前」，选择带时间的记录后点击「恢复所选」。
- 修改设置后自动备份，恢复默认、应用方案和恢复历史前也会备份；保留最近 **20** 条，覆盖任务与花圃的尺寸、样式、字段、筛选，以及截图主题与清晰度倍数。
- 历史独立保存在当前浏览器、当前网站的 `localStorage` 中。更新脚本时，如果脚本管理器将设置清空，重新打开网页会尝试从最近备份恢复缺失的设置；已有设置优先使用。该功能只覆盖本脚本，不会保存或恢复其他脚本。
- 清除网站数据、更换浏览器或设备后，本地历史不可用。网站存储不可用时会提示备份失败，并阻止「恢复默认」或历史恢复覆盖未备份的配置；普通设置仍由脚本管理器保存。
- **首次升级提醒：**旧版尚未生成这份独立备份。如果首次更新就清空原设置，新版无法找回已删除的配置；本次更新请保留设置，先让新版正常运行一次。
